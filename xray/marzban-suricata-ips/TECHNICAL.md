# محافظ ترافیک خروجی نود مرزبان

این فایل برای نگه‌داری و بررسی فنی است. راهنمای اپراتور در [README.md](README.md) قرار دارد.

## سیاست خطای جریان TCP

از نسخهٔ ۲.۱.۱، گزینهٔ `stream.drop-invalid` صریحاً `false` است. این گزینه از سیاست خطای حافظه مستقل است؛ در [کد Suricata 7.0.3](https://github.com/OISF/suricata/blob/suricata-7.0.3/src/stream-tcp.c) به‌صورت پیش‌فرض فعال است و خطای اعتبارسنجی جریان را با علت `stream_error` مسدود می‌کند. کاربرد آن در [راهنمای تنظیم جریان TCP](https://docs.suricata.io/en/suricata-7.0.3/configuration/suricata-yaml.html) توضیح داده شده است.

هدف این بسته، مسدودکردن امضاهای منتخب بدافزار با احتمال اختلال کمتر روی نود است. بنابراین خطای وضعیت TCP به‌تنهایی معیار مسدودسازی نیست. حالت `stream.inline` و قوانین `drop` فعال می‌مانند؛ اما اعتبارسنجی سخت‌گیرانهٔ جریان دیگر مانع عبور این بسته‌ها نمی‌شود و ممکن است حفاظت در برابر روش‌های دورزدن تحلیل TCP کاهش یابد. علتِ نامعتبر دیده‌شدن یک بسته، از شمارندهٔ `stream_error` به‌تنهایی قابل تشخیص نیست.

نمایش زنده علت مسدودسازی‌ها را جدا نشان می‌دهد. وجود بسته‌های مسدودشده خارج از علت مستقیم `rules`، وضعیت هشدار می‌دهد؛ این شمارنده‌ها از شروع موتور جمع می‌شوند و اثبات بدافزار نیستند. در موتورهای فاقد جزئیات علت، مقدار نامشخص با برچسب `unattributed` نمایش داده می‌شود.

## نسخه و ارتقای برنامه

نسخهٔ برنامه در `VERSION` نگه‌داری می‌شود و پس از نصب در `/etc/marzban-ips/version` قرار می‌گیرد. پیش از انتشار هر تغییر قابل نصب، نسخه را افزایش دهید. دستور `upgrade` نسخهٔ شاخهٔ `main` را از GitHub می‌خواند، commit آن را مشخص می‌کند و فایل‌های همان commit را دریافت می‌کند. نسخهٔ برابر یا قدیمی‌تر، بدون گزینهٔ `--force` دوباره نصب نمی‌شود.

ارتقا ابتدا پیکربندی جدید و قوانین موجود را بررسی می‌کند؛ سپس از فایل‌های تحت مدیریت ابزار در `/var/lib/marzban-ips/backups/` نسخهٔ پشتیبان می‌گیرد. طی جایگزینی، بررسی ترافیک موقتاً متوقف است. در خطای جایگزینی یا شروع موتور، فایل‌های قبلی برگردانده می‌شوند. حالت خاموش، وضعیت فعال تایمرها، شمارهٔ صف و فایل‌های override سرویس‌ها حفظ می‌شوند. تنظیمات تولیدشدهٔ موتور با پیش‌فرض‌های نسخهٔ جدید بازسازی می‌شوند؛ تنظیمات سفارشی این فایل در نسخهٔ پشتیبان قابل بازیابی‌اند.

دستورهای نگه‌داری:

```bash
sudo marzban-ips version
sudo marzban-ips upgrade
sudo marzban-ips upgrade --force
sudo marzban-ips diagnostics
```

برای ارتقای نصب‌های قدیمی که هنوز دستور `upgrade` ندارند، نصب‌کنندهٔ آنلاین را دوباره اجرا کنید؛ وجود نصب قبلی تشخیص داده می‌شود و مسیر ارتقا اجرا می‌شود.

## سازگاری و نمایش زنده

شرط نسخهٔ سیستم‌عامل، Ubuntu 22.04 یا جدیدتر است. بستهٔ [Suricata در Ubuntu 22.04](https://packages.ubuntu.com/jammy/suricata) از خانوادهٔ ۶.x است. مولد پیکربندی نسخهٔ موتور را شناسایی می‌کند؛ برای ۶.x گزینه‌های سیاست خطای جدید را حذف می‌کند و برای ۷.x و بالاتر سیاست عبور هنگام خطا را صریح تنظیم می‌کند. تفاوت رفتار پیش‌فرض این دو خانواده در [مستندات رسمی سیاست‌های خطا](https://docs.suricata.io/en/suricata-6.0.20/configuration/exception-policies.html) آمده است. وجود پشتیبانی NFQUEUE و اعتبارسنجی پیکربندی و قوانین نیز الزامی است؛ پذیرش نسخهٔ سیستم‌عامل به‌تنهایی کافی نیست.

نمایش `live` هر دو ثانیه، آمار رابط‌ها را از `/proc/net/dev`، وضعیت سرویس و مصرف منابع را از systemd، شمارنده‌های مسیر را از nftables و رخدادها و آمار موتور را از EVE می‌خواند. آمار موتور هر ده ثانیه ثبت می‌شود. نمایش زنده بسته یا محتوای ترافیک را ذخیره نمی‌کند و فقط هنگام اجرای دستور منابع مصرف می‌کند.

نرخ رابط‌ها جدا نمایش داده می‌شود؛ جمع‌کردن رابط مجازی و فیزیکی می‌تواند ترافیک را دوبار بشمارد. شمارنده‌های `client-ingress` و `client-egress` ساق اتصال کاربران به میزبان را نشان می‌دهند؛ این شمارنده‌ها شامل اتصال‌های دیگر میزبان هم می‌شوند و فقط مختص مرزبان نیستند. شمارنده‌های `ips-ingress` و `ips-egress` بسته‌های عرضه‌شده به صف را نشان می‌دهند، حتی اگر در حالت عبور هنگام خطا بررسی نشوند.

وضعیت `RUNNING` فقط با موتور فعال، مسیر صف موجود و آمار تازهٔ پردازش بسته نمایش داده می‌شود. آمار قدیمی‌تر از ۴۵ ثانیه، گم‌شدن مسیر، رشد افت صف، صف طولانی یا عرضهٔ پیوستهٔ بسته بدون پیشرفت شمارندهٔ موتور، وضعیت هشدار یا انتظار می‌دهد. نبود هشدار اثبات سالم‌بودن همهٔ ترافیک نیست. ترافیک ورودی VPN رمز‌شده است؛ بررسی بدافزار عمدتاً در مسیر خروجی مستقیم Xray و پاسخ مقصدها انجام می‌شود.

این ابزار ارتباط‌های خروجی مشکوک به فرمان‌دهی بدافزار را با قوانین منتخب Suricata بررسی و مسدود می‌کند. برای **نود مرزبان روی Ubuntu 22.04 و بالاتر و Docker با شبکهٔ `host`** است. نصب را روی خود نود انجام دهید.

**نیازی به واردکردن IP نیست.** آدرس‌های IPv4، IPv6 و مبدأ مسیرها خودکار خوانده می‌شوند؛ چند IP و IP شناور هم پشتیبانی می‌شوند. تغییر آدرس‌ها هر پنج دقیقه بررسی می‌شود.

> این ابزار ارتباط بدافزار را محدود می‌کند؛ بدافزار را از دستگاه کاربر پاک نمی‌کند. تشخیص بر پایهٔ امضاهای شناخته‌شده است و پوشش همهٔ تهدیدها تضمین نمی‌شود.

## نصب

با SSH وارد نود شوید و دستور زیر را اجرا کنید:

```bash
curl -fsSL "https://raw.githubusercontent.com/KAJOOSH/OpsVault/refs/heads/main/xray/marzban-suricata-ips/install-online.sh" -o /tmp/install-marzban-ips.sh \
  && sudo bash /tmp/install-marzban-ips.sh
```

برای نصب از فایل‌های دانلودشده، داخل پوشهٔ همین ابزار اجرا کنید:

```bash
sudo bash install.sh
```

نصب‌کننده بسته‌های موردنیاز، سرویس‌ها و به‌روزرسانی روزانهٔ قوانین را آماده می‌کند. دسترسی به مخازن Ubuntu، مخزن Universe و منبع قوانین ET Open لازم است. نصب در حضور یک پردازش فعال Suricata یا فایل‌های نصب قبلی متوقف می‌شود. برای نصب مجدد، ابتدا دستور حذف پایین را اجرا کنید.

دستور نصب آنلاین، نسخهٔ منتشرشده در شاخهٔ `main` را دریافت می‌کند؛ برای آزمودن تغییرات محلی پیش از انتشار، از روش نصب با فایل‌ها استفاده کنید.

## بررسی بعد از نصب

```bash
sudo marzban-ips status
sudo marzban-ips test
sudo marzban-ips alerts
```

- دستور `status` وضعیت سرویس، شمارندهٔ بسته‌ها، آدرس‌های شناسایی‌شده و محدودیت منابع را نشان می‌دهد.
- دستور `test` یک درخواست HTTP بی‌خطر می‌فرستد. نتیجهٔ `PASS` یعنی همان درخواست تازه مسدود شده است. نتیجهٔ `INCONCLUSIVE` نیاز به بررسی DNS، دسترسی خروجی HTTP و لاگ‌ها دارد.
- دستور `alerts` حداکثر ۵۰ رخداد مسدودشدهٔ اخیر را نشان می‌دهد. خالی‌بودن آن به‌تنهایی نشانهٔ مشکل نیست.

تست داخلی از خود سرور اجرا می‌شود. برای اطمینان از پوشش نود، از دستگاهی که به VPN همین نود وصل است نیز اجرا کنید و سپس لاگ نود را ببینید:

```bash
curl --noproxy '*' --max-time 8 -H 'Host: manual.ips-test.invalid' http://example.com/
```

انتظار می‌رود درخواست متوقف شود و در خروجی `sudo marzban-ips alerts` شناسهٔ `9900001` دیده شود. این آزمون فقط مسیر HTTP آزمایشی را بررسی می‌کند. اگر از پراکسی محلی برای اتصال استفاده می‌کنید، درخواست را از همان پراکسی بفرستید؛ گزینهٔ `--noproxy '*'` را حذف کنید و نشانی پراکسی خود را به curl بدهید.

## دستورهای روزمره

```bash
sudo marzban-ips disable    # خاموش‌کردن فوری بررسی و آزادکردن منابع
sudo marzban-ips enable     # روشن‌کردن دوباره
sudo marzban-ips update     # دریافت و اعتبارسنجی قوانین منتخب
sudo marzban-ips refresh    # بررسی فوری تغییر IP
sudo marzban-ips alerts     # دیدن ارتباط‌های مسدودشده
sudo marzban-ips status     # وضعیت و مصرف منابع
sudo marzban-ips uninstall  # حذف ابزار؛ نگه‌داشتن لاگ‌ها و حافظهٔ موقت قوانین
```

حالت خاموش بعد از ریبوت حفظ می‌شود. به‌روزرسانی قوانین، ابزار خاموش را روشن نمی‌کند.

## مصرف منابع و محدودیت‌ها

- فقط قوانین منتخب `ET BOTCC`، `ET CNC`، `Andromeda` و `Avalanche` برای مسدودسازی بارگذاری می‌شوند. قوانین پشتیبانِ وضعیت اتصال، در صورت نیاز، با حالت هشدار نگه داشته می‌شوند.
- سقف CPU موتور برابر ۵۰٪ یک هسته و سقف RAM آن ۵۱۲ مگابایت است. مصرف واقعی به ترافیک بستگی دارد؛ این اعداد تضمین سرعت یا مصرف ثابت نیستند. به‌روزرسانی روزانه موقتاً پردازش جداگانه‌ای با سقف ۷۶۸ مگابایت دارد؛ بررسی تغییر آدرس نیز ممکن است موقتاً تا ۵۱۲ مگابایت مصرف کند. این کارها هم‌زمان با هم اجرا نمی‌شوند، اما موتور اصلی می‌تواند فعال باشد.
- هنگام توقف موتور یا پرشدن صف، ترافیک بدون بررسی عبور می‌کند تا احتمال قطعی کمتر شود. محدودیت CPU در ترافیک زیاد می‌تواند تأخیر یا عبور بسته‌های بررسی‌نشده ایجاد کند.
- فقط هشدارها و آمار ثبت می‌شوند؛ محتوای بسته‌ها و فایل‌های کاربران ذخیره نمی‌شود. آدرس و پورت ارتباط در هشدارها وجود دارد.
- حجم لاگ هر پنج دقیقه بررسی می‌شود؛ پس از رسیدن به ۱۰ مگابایت، چرخش با نگه‌داری سه نسخه انجام می‌شود. بین دو بررسی امکان رشد بیشتر وجود دارد. چرخش لاگ ممکن است چند رخداد هم‌زمان را از دست بدهد.
- ترافیک HTTPS و تونل‌های رمز‌شده رمزگشایی نمی‌شوند. تشخیص فقط بر اساس بخش‌های قابل‌مشاهده و امضاهای موجود است. عمق بازسازی هر جریان نیز برای کاهش مصرف، ۲۵۶ کیلوبایت است.
- این روش خروجی مستقیم میزبان را بررسی می‌کند؛ ارتباط‌های خود سرور هم در همین محدوده‌اند. ترافیک کاربران از یک پردازش مشترک Xray خارج می‌شود و از این لاگ به‌تنهایی نمی‌توان نام کاربر مرزبان را تشخیص داد.
- خروجی از WARP، پراکسی بالادستی، شبکهٔ bridge یا مسیرهای ویژه ممکن است به‌صورت رمز‌شده یا در مسیر دیگری عبور کند و پوشش این ابزار را نداشته باشد.

در سرور پرترافیک، ابتدا در ساعت خلوت نصب کنید و سرعت VPN و خروجی `status` را بسنجید. اگر افت سرعت یا اختلال داشتید، `sudo marzban-ips disable` را اجرا کنید.

## آدرس شناور چگونه پوشش داده می‌شود؟

فیلتر به IP عمومی خاصی وابسته نیست و همهٔ رابط‌ها را پوشش می‌دهد. خروجی مستقیم، در مسیر `OUTPUT` پیش از SNAT و پاسخ آن در مسیر `INPUT` پس از ترجمهٔ برگشتی آدرس بررسی می‌شود. بنابراین IP شناور ورودی می‌تواند با IP خروجی متفاوت باشد. در NAT معمول ارائه‌دهنده نیز لازم نیست IP عمومی خروجی روی رابط سرور ثبت شده باشد. این توضیح بر اساس [ترتیب مسیرهای Netfilter](https://wiki.nftables.org/wiki-nftables/index.php/Netfilter_hooks) است؛ مسیرهای تونلی یا سفارشی باید جداگانه آزمایش شوند.

در شروع موتور و هر پنج دقیقه، آدرس‌ها از خود Linux خوانده می‌شوند. فقط هنگام تغییر آدرس، پیکربندی بررسی و موتور دوباره راه‌اندازی می‌شود؛ طی این فاصلهٔ کوتاه بررسی ترافیک متوقف است. پس از جابه‌جایی IP می‌توانید دستور `refresh` را برای اعمال زودتر اجرا کنید.

## رفع مشکل

```bash
sudo marzban-ips disable
sudo journalctl -u marzban-suricata -u marzban-ips-update -u marzban-ips-refresh -n 80 --no-pager
```

اگر نصب نیمه‌کاره ماند، پس از دیدن خطا `sudo marzban-ips uninstall` را اجرا کنید و دوباره نصب کنید. دستور حذف بسته‌های Ubuntu، فایل اصلی تنظیمات Suricata، لاگ‌ها و حافظهٔ موقت قوانین را حذف نمی‌کند.

فایل تنظیمات اختصاصی در `/etc/suricata/marzban-ips.yaml`، قوانین در `/var/lib/marzban-ips/rules/` و لاگ در `/var/log/marzban-suricata/eve.json` است. تنظیمات مرزبان و Xray تغییر نمی‌کنند و جدول فایروال مستقل `inet marzban_ips` استفاده می‌شود. اجرای `nft flush ruleset` جزو این ابزار نیست. بارگذاری مجدد فایروال توسط ابزارهای دیگر ممکن است این جدول را حذف کند؛ بعد از چنین تغییری، `sudo marzban-ips enable` را اجرا کنید.

رفتار عبور ترافیک در خطا بر اساس [سیاست‌های خطای Suricata](https://docs.suricata.io/en/suricata-7.0.15/configuration/exception-policies.html) تنظیم شده و دریافت قوانین از [ابزار رسمی Suricata Update](https://suricata-update.readthedocs.io/en/1.3.3/update.html) استفاده می‌کند. وضعیت آزمون‌ها در [TESTING.md](TESTING.md) آمده است.
