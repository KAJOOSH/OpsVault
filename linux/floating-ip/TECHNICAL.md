# راهنمای فنی Floating IP

راهنمای استفادهٔ روزمره در [README.md](README.md) است.

## پیش‌نیازها

این ابزار برای Ubuntu با Netplan و systemd نوشته شده است. فرمان‌های `ip`، `iptables`، `iptables-restore`، `curl` و `flock` باید نصب باشند. فرمان‌های مدیریتی با دسترسی root اجرا می‌شوند.

رابط پیش‌فرض `eth0` است. اگر سرور رابط دیگری دارد:

```bash
sudo env FLOATING_IP_INTERFACE=ens3 floating-ip add FLOATING_IP --snat
sudo env FLOATING_IP_INTERFACE=ens3 floating-ip snat remove
```

به‌جای `FLOATING_IP` آدرس شناور را وارد کنید. فایل Netplan این ابزار برای یک رابط است؛ پس از افزودن آدرس‌ها، نام رابط را تغییر ندهید.

## تشخیص آی‌پی اصلی و تنظیم خروجی

آی‌پی اصلی از مقدار `src` در خروجی این فرمان گرفته می‌شود:

```bash
ip -4 route get 1.1.1.1 oif eth0
```

اگر این تشخیص شکست بخورد یا یک آی‌پی شناور انتخاب شود، مبدا را دستی وارد کنید. به‌جای `MAIN_IP` آی‌پی اصلی سرور را بنویسید:

```bash
sudo floating-ip snat add FLOATING_IP MAIN_IP
```

در VPNهای تونلی، مبدا بسته ممکن است زیرشبکهٔ کاربران باشد. در این حالت به‌جای `VPN_SUBNET`، زیرشبکه را همراه با پیشوند آن وارد کنید:

```bash
sudo floating-ip snat add FLOATING_IP VPN_SUBNET
sudo floating-ip snat remove VPN_SUBNET
```

برای CIDRهای هم‌پوشان، پیشوند طولانی‌تر اولویت دارد. تنظیمات forwarding و قواعد مجازکردن ترافیک VPN باید جداگانه آماده باشند.

قواعد SNAT در زنجیرهٔ `OPSVAULT_FLOATING_IP` قرار می‌گیرند و از ابتدای `POSTROUTING` به آن ارجاع داده می‌شود. اثر تغییرات روی اتصال‌های جدید است؛ اتصال‌های قبلی ممکن است نگاشت conntrack قبلی را نگه دارند. [توضیح رسمی SNAT](https://www.netfilter.org/documentation/HOWTO/NAT-HOWTO-۶.html)

## ذخیره و بازیابی

- آدرس‌ها: `/etc/netplan/60-floating-ip.yaml`
- نگاشت‌های خروجی: `/etc/floating-ip/snat.tsv`
- بازیابی پس از راه‌اندازی: `floating-ip-snat.service`

رابط هر نگاشت ذخیره می‌شود؛ بازیابی به متغیر محیطی نیاز ندارد. قواعد سایر ابزارها پاک نمی‌شوند. اگر ابزار دیگری فایروال را بازنشانی کرد، قواعد را دوباره اعمال کنید:

```bash
sudo floating-ip snat restore
```

پیش از تغییر Netplan، نسخهٔ پشتیبان ساخته می‌شود. در صورت خطا، برای بازگرداندن تنظیمات قبلی تلاش می‌شود. اگر مرحلهٔ SNAT در `add --snat` شکست بخورد، آدرس اضافه‌شده باقی می‌ماند؛ پس از رفع خطا همان فرمان را دوباره اجرا کنید.

## انتشار نسخهٔ جدید

فایل [VERSION](VERSION) شمارهٔ نسخهٔ منتشرشده را نگه می‌دارد. دستور `update` ابتدا همین فایل کوچک را دریافت می‌کند؛ اگر نسخه جدیدتر نباشد، فایل اسکریپت دانلود نمی‌شود.

برای انتشار:

۱. شمارهٔ نسخه را در فایل `VERSION` افزایش دهید؛ مثلاً `2.0.0` به `2.0.1`.

۲. مقدار `VERSION` داخل `floating-ip.sh` را نیز به همان شماره تغییر دهید. این مقدار برای نمایش نسخهٔ نصب‌شده و تطبیق فایل دانلودشده با نسخهٔ اعلام‌شده نگه داشته می‌شود.

۳. هر دو فایل را همراه با تغییرات در یک commit در شاخهٔ `main` منتشر کنید.

۴. روی سرور اجرا کنید:

```bash
sudo floating-ip update
floating-ip version
```

شمارهٔ نسخهٔ فایل دانلودشده باید با فایل `VERSION` یکسان باشد. فایل نسخهٔ نامعتبر، اختلاف شمارهٔ نسخه‌ها، دریافت ناموفق یا خطای نحو Bash باعث توقف به‌روزرسانی می‌شود. پس از کامل‌شدن انتشار می‌توان فرمان را دوباره اجرا کرد.

فایل اجرایی با جایگزینی اتمی نصب می‌شود؛ آدرس‌ها و نگاشت‌ها حفظ می‌شوند و شبکه دوباره اعمال نمی‌شود. دریافت از مخزن با HTTPS انجام می‌شود؛ بررسی نسخه و نحو جای امضای انتشار را نمی‌گیرد.

## بازگشت به نسخهٔ قبلی

نسخهٔ قبلی در `/usr/local/bin/floating-ip.backup` ذخیره می‌شود. برای بازگشت:

```bash
sudo install -o root -g root -m 755 /usr/local/bin/floating-ip.backup /usr/local/bin/floating-ip
```

این پشتیبان فقط فایل اجرایی را برمی‌گرداند. اگر نسخهٔ قبلی از SNAT پشتیبانی نمی‌کند، پیش از بازگشت همهٔ نگاشت‌ها را با `snat remove` حذف کنید؛ برای مبداهای دستی، همان مبدا را به فرمان بدهید. سپس سرویس را غیرفعال کنید:

```bash
sudo systemctl disable --now floating-ip-snat.service
```

## بررسی توسعه

تست‌های شبیه‌سازی‌شده در پوشهٔ موقت اجرا می‌شوند و تنظیمات واقعی شبکه و systemd را تغییر نمی‌دهند:

```bash
bash linux/floating-ip/tests/test_floating_ip.sh
```

این بررسی جای اجرای آزمایشی روی Ubuntu با Netplan و iptables واقعی را نمی‌گیرد.
